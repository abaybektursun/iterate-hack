Unsticking research agents

An agent that improves a program by trial and error tends to lock onto its first idea and only tweak it. We test the published fixes for this, Fork-and-Flush and Forgetting, against a plain single run, at the same budget, and add our own: flush an agent only when a judge sees it stuck in one approach.

The setup

Two test problems with an automatic score

Each run gives an agent 40 tries. It writes a whole program, the program is scored, the agent sees the score and writes the next version. The two problems are open-ended, so there is always room to do better.

circles26

Place 26 circles in a unit square without overlap; maximize the sum of radii. Best published: about 2.636.

AHC014 (RectJoin)

AtCoder Heuristic Contest 014 via Frontier-CS problem 159, the task both papers report. Each move adds a dot that closes a rectangle; dots far from the center count more. Score: share of a strong reference solution (1.0 = reference).

The strategies

Seven ways to spend the same 40 tries

Each strategy only decides which chat history and which starting program the next call gets. Bars are chats on a timeline of 40 tries; a ring marks a flush, where the chat is cleared and restarts from the best program so far.

Fork-and-Flush forks at 0 %, 33 % and 66 % of the budget, 4 branches of 2 tries each; the best branch leads. Forgetting flushes every agent every 10 tries, and agents see each other's top scores. The basin rings are the real flushes from the circles26 basin run; the random control gets the same number at random times (drawn here at example times).

Finding 1 · gpt-5.4-mini · circles26 · 5 seeds

A weak model gets stuck, and flushing helps it least badly

Fork-and-Flush ends highest (mean 2.438) and a single long chat lowest (2.140), with the same order at equal dollar spend. But no arm really beats the starter's 2.541: the model hand-places circles and almost never writes an optimizer.

Best score so far after each try, mean of 5 seeds (thick) and each seed (thin). Dashed: the starter program the agents begin from. 4 arms × 5 seeds × 40 tries, 6.37 USD.

Finding 2 · gpt-5.4-mini · AHC014 · 1 seed

On the contest task, every arm that flushes beats every arm that does not

Forgetting 0.439 and the basin trigger 0.362 lead; a single chat gets 0.240. Fork-and-Flush against the same forks without the flush (0.296 vs 0.259) isolates the flush itself. One seed: a hint, not a result.

Best score so far per arm, one seed each. Dashed: the starter (no moves, 0.222). The random-timing control was stopped at 30 of 40 when an environment bug was found.

Mechanism · gpt-5.4-mini · circles26 basin run

What the judge sees: approaches over time

An LLM judge (gpt-6.1-sol, about 0.004 USD per call) labels each submission by its method, not its numbers. When an agent's last 4 tries sit in one approach without a new team best, it is flushed and restarted from the best program of another approach, told what the team already tried.

Each dot is one submission, placed by try number and agent; color is its basin; hollow dots were invalid. Vertical rings: the 3 flushes, all after try 16. Hover a dot for the idea line.

Weak point. On AHC014 the judge put all 40 submissions of the basin run into one basin, "greedy rectangle completion", so those flushes were set by the 4-try window, not by a change of approach. The judge prompt has since been made task-neutral; its labels still need checking against the code.

Finding 4 · SWE-2 · AHC014 · 6 runs per arm

The planned test failed; single runs are the unreliable ones

Means are in the predicted order, Fork-and-Flush 0.592 > parallel 0.577 > single 0.546, but Fork-and-Flush beats single with only p = 0.197 (plan: p < 0.05), so the prediction is refuted at this size. What stands out instead: single runs spread 3.5 times wider, and their worst run is far below every other.

Each dot is one 40-try run's best validation score; the tick is the mean. One-sided exact rank-sum, 6 vs 6: Fork-and-Flush > single p = 0.197, > parallel p = 0.155. Spread (found after looking): single SD 0.082 vs 0.024, p = 0.042.

The worst single run, try by try. At try 2 it settled on a move set where every 45° rectangle is a square, and kept it for 38 more tries (case 1: 22 tilted squares, 0 tilted rectangles with unequal sides, 54 moves). In Fork-and-Flush seed 4, a fresh branch at the opening fork allowed unequal sides and jumped from 0.388 to 0.522 (case 1: 28 such rectangles, 100 moves).

Finding 5 · gpt-5.4-mini · both tasks · 1 seed

A flush does not change which method the model picks; assigning one does

A fresh chat samples from the same model, so it tends to choose the same method again. New arm, assigned methods: before each fork of Fork-and-Flush, one extra call lists 4 different methods, and each fresh branch is told to implement one. The list is written by gpt-5.4-mini itself or by a stronger model (gpt-6.1-sol).

On circles26 both assigned arms beat the starter, which no published strategy does: 2.636 with the strong list (the best published packing) and 2.628 with the model's own list, against 2.535 for Fork-and-Flush. On AHC014 the own-list arm is second (0.371) behind Forgetting (0.439), and the strong list hurts (0.242).

circles26, best score so far. Dashed: the starter. Two controls: a single chat shown the same lists and asked to pick one, and a single chat that is re-shown its best program every 10 tries (rollback, chat kept). This run had numpy and scipy available.

The model knows the method and does not choose it. Its own first list contains a scipy optimizer. Told to implement it, a fresh branch does. Shown the same lists in one chat and asked to pick, it wrote a hand-made layout 40 times out of 40.

Rollback matches the flush here. Keeping the whole chat and only re-showing the best program ends at 2.541, Fork-and-Flush at 2.535.

AHC014, best score so far. Thin lines: Forgetting and Fork-and-Flush from Finding 2. Two arms from the literature: fresh branches told what was tried but given no method (SwarmResearch, arXiv 2607.02807) and successive halving of 8 chats (arXiv 2607.18235). Both stop at 0.295, the score of plain greedy rectangle completion, as Fork-and-Flush does.

Where it fails. The strong model listed beam search, tree search and large-neighbourhood search; gpt-5.4-mini's programs for them were invalid or made no move (18 of 40 valid). Adding assignment to Forgetting gave 0.324, below plain Forgetting: each method got 2 or 3 tries. A method helps only if the agent can implement it in the tries its branch gets.

Caveats

What these numbers do not show yet

  • Finding 5 is one seed per arm, and its Forgetting and Fork-and-Flush reference lines on AHC014 come from the earlier run. Literature arms follow the papers' descriptions, not their code.
  • Six runs per arm in Finding 4, one elsewhere outside Finding 1. Differences of a few hundredths can be noise; seeds get added only for an arm that wins.
  • Until the bug was found, programs ran on a Python without numpy and scipy. gpt-5.4-mini's 10 attempts to use them all failed; AHC014 was unaffected (no imports). SWE-2 ran with both.
  • SWE-2 runs inside Devin's own agent prompt, so a model comparison also changes the harness.
  • "Uses an optimizer" is a keyword check on the code (scipy, minimize, SLSQP, gradient, anneal, penalty), not the judge.
